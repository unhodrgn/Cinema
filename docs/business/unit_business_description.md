# 단위 업무 기술서

**프로젝트명:** 영화관 예매 및 좌석 관리 시스템 (Cinema Reservation System)

---

## 1. 단위 업무 기술서 개요

### 1.1 목적

본 문서는 업무 기능도(`business_function.md`)에서 정의한 14개 업무 기능을 단위 업무별로 구체화하여 기술한 문서이다. 각 단위 업무의 목적, 사전 조건, 입력 정보, 처리 내용, 출력 정보, 예외 및 제약사항을 일관된 형식으로 정의함으로써 이후 업무 흐름도 작성, 데이터베이스 설계 및 응용 프로그램 개발의 기준으로 활용한다.

### 1.2 범위

본 문서는 프로젝트 개요서(`project_overview.md`)와 업무 기능도(`business_function.md`)에서 승인된 범위, 용어, 사용자 역할, 기능 번호 및 업무 규칙을 그대로 따르며, 업무 규칙 결정 기록(`business_rules_decision_log.md`, BR-DL-001)에서 승인된 결정 사항을 함께 반영한다.

| 항목 | 범위 |
|---|---|
| 영화관 | 1개 |
| 상영관 | 5개 (상영관당 좌석 50석, 총 250석) |
| 영화 | 샘플 영화 6편 |
| 상영 일정 | 연속 14일간 총 280회 |
| 사용자 역할 | 고객(CUSTOMER), 관리자(ADMIN) |
| 기술 환경 | Python, Flask, PostgreSQL, React, TypeScript |
| 대상 업무 | 14개 단위 업무 (CM-01, CM-02, C-01 ~ C-09, A-01 ~ A-03) |

### 1.3 업무 규칙 참조

각 단위 업무의 예외 및 제약사항에는 다음 두 종류의 업무 규칙 근거를 함께 표기한다.

1. **기존 업무 규칙:** 프로젝트 개요서 6장에 정의된 업무 규칙 번호 BR-01 ~ BR-15
2. **추가 승인 결정:** 업무 규칙 결정 기록 BR-DL-001(버전 1.0, 2026-11-17 승인)에 기록된 결정 D1 ~ D6. 본 문서에서는 `(D1)`과 같이 표기한다.

BR-DL-001은 프로젝트 개요서와 업무 기능도를 보완하는 문서이며, 기존에 명확히 규정되지 않았던 사항에 대해서는 BR-DL-001의 결정이 우선한다. 업무 기능 번호와 승인된 범위는 변경되지 않는다.

| 결정 | 주요 내용 | 주로 반영되는 단위 업무 |
|---|---|---|
| D1 | 예매를 취소하면 예매 상태를 `CANCELLED`로 변경하고 예매 좌석 상세 정보(`BOOKING_SEATS`)를 모두 삭제하되, 예매 본 정보(`BOOKINGS`)는 이력으로 보존한다. | C-08, C-09, A-03 |
| D2 | 상영 일정을 참조하는 예매 기록이 하나라도 있으면(예매 상태와 무관하게) 해당 상영 일정의 실제 변경을 허용하지 않으며, 이미 시작되었거나 예매 기록이 있는 상영 일정·영화는 삭제할 수 없다. | A-01, A-02 |
| D3 | 미결제 예매는 예매 확정 후 10분이 지나면 `EXPIRED`로 변경되고 좌석 상세 정보가 삭제되어 좌석이 해제된다. | C-04 ~ C-09, A-03 |
| D4 | 영화·상영 일정 조회, 좌석 현황 조회, 좌석 선택은 로그인 없이 이용할 수 있으며, 로그인은 예매 확정 시점에 필수이다. | CM-01, CM-02, C-02 ~ C-06 |
| D5 | 회원가입 입력 항목은 계정 ID와 비밀번호뿐이며, 영화 정보는 기본 6개 속성(`title`, `genre`, `duration_minutes`, `rating`, `synopsis`, `release_date`)과 선택적 포스터 경로(`poster_url`)를 사용한다. | C-01, C-02, A-01 |
| D6 | 좌석당 관람 가격은 상영 일정별로 정의하며, 예매 시점의 좌석별 가격을 예매 좌석 상세 정보에 저장한다. | C-03, C-06, A-02 |

**상태값 정의.** 본 문서는 BR-DL-001 3장의 상태값을 다음과 같이 통일하여 사용한다. 예매 상태와 결제 상태는 서로 독립된 별개의 속성이다.

| 구분 | 상태값 | 의미 | 좌석 점유 | 예매 좌석 상세 정보 |
|---|---|---|---|---|
| 예매 상태 | `BOOKED` (예매 완료) | 예매가 확정되었으며 취소 또는 만료되지 않은 상태 | 점유한다. 단, 미결제인 경우 결제 기한(`expires_at`)까지만 점유한다. | 유지된다. |
| 예매 상태 | `CANCELLED` (취소) | 고객이 상영 시작 전에 예매 전체를 취소한 상태 | 점유하지 않는다. | 삭제된다. |
| 예매 상태 | `EXPIRED` (만료) | 결제 기한 내에 결제가 완료되지 않은 상태 | 점유하지 않는다. | 삭제된다. |
| 결제 상태 | `UNPAID` (미결제) | 모의 결제가 완료되지 않은 상태 | — | — |
| 결제 상태 | `PAID` (결제 완료) | 모의 결제가 정상적으로 완료된 상태 | — | — |

- 결제가 완료된 예매(`PAID`)가 이후 취소되면 결제 상태는 `PAID`로 유지되고 예매 상태만 `CANCELLED`로 변경된다. 환불 처리는 본 시스템의 범위에 포함하지 않으며 환불 상태나 환불 절차를 정의하지 않는다.
- 만료된 예매는 결제 상태가 `UNPAID`로 유지되고 예매 상태만 `EXPIRED`로 변경된다.

**공통 용어.** 본 문서에서 사용하는 다음 용어는 아래와 같이 정의한다.

| 용어 | 정의 |
|---|---|
| 유효한 예매 | 예매 상태가 `BOOKED`이면서, 결제 상태가 `PAID`이거나 결제 상태가 `UNPAID`이고 현재 시각이 `expires_at`보다 이른 예매이다. 유효한 예매에 포함된 좌석만 해당 상영 일정에서 점유된 좌석으로 본다. `CANCELLED` 및 `EXPIRED` 예매는 유효한 예매가 아니다. (BR-08, D1, D3) |
| 결제 기한 | 예매 확정 일시(`booked_at`)로부터 10분 후의 일시이며 `expires_at`으로 저장한다. 10분은 예매 확정이 성공적으로 기록된 시점부터 계산하며, 좌석 선택 시점부터 계산하지 않는다. (D3) |
| 만료 처리 | 현재 시각이 `expires_at`과 같거나 이후인 `BOOKED` + `UNPAID` 예매에 대하여 예매 상태를 `EXPIRED`로 변경하고, 해당 예매의 예매 좌석 상세 정보를 모두 삭제하여 좌석을 함께 해제하며, 예매 본 정보는 이력으로 보존하는 처리이다. 상태 변경과 좌석 해제는 모두 성공하거나 모두 실패해야 하며, 같은 예매에 반복하여 수행하더라도 결과가 달라지지 않는다. 만료 처리의 실행 방식(정기 처리, 요청 시점 처리 등)은 응용 프로그램 설계에서 정하되, 결제 기한은 반드시 지켜져야 한다. (D3) |

결제 기한의 경계 조건은 다음과 같다. 현재 시각이 `expires_at`보다 엄격하게 이른 경우에만 결제할 수 있으며, 현재 시각이 `expires_at`과 같거나 이후이면 미결제 예매는 만료된 것으로 보아 결제를 허용하지 않는다. (D3)

## 2. 업무 기술서 작성 기준

모든 단위 업무는 다음 9개 항목으로 동일하게 기술한다.

| 번호 | 항목 | 작성 기준 |
|---|---|---|
| 1 | 업무 ID | 업무 기능도에서 부여한 기능 번호이다. 공통 기능은 `CM-`, 고객 전용 기능은 `C-`, 관리자 전용 기능은 `A-`로 시작한다. |
| 2 | 업무명 | 업무 기능도에 정의된 기능명이다. |
| 3 | 담당 사용자 | 해당 업무를 수행할 수 있는 사용자 역할(CUSTOMER, ADMIN)이다. |
| 4 | 업무 목적 | 해당 업무가 필요한 이유와 달성하려는 결과이다. |
| 5 | 사전 조건 | 업무를 시작하기 위해 미리 충족되어야 하는 상태나 조건이다. |
| 6 | 입력 정보 | 사용자가 제공하거나 업무 수행 중 참조하는 정보이다. |
| 7 | 처리 내용 | 업무 수행 중 확인하는 조건과 수행하는 처리를 순서대로 나열한 것이다. |
| 8 | 출력 정보 | 업무 수행의 결과로 사용자에게 제공되거나 저장·변경되는 정보이다. |
| 9 | 예외 및 제약사항 | 업무를 수행할 수 없는 경우, 오류 처리 방식 및 반드시 지켜야 하는 업무 규칙이다. |

## 3. 단위 업무 상세 기술

### 3.1 회원 관리

#### 3.1.1 CM-01 로그인

| 항목 | 내용 |
|---|---|
| 업무 ID | CM-01 |
| 업무명 | 로그인 |
| 담당 사용자 | CUSTOMER, ADMIN |
| 업무 목적 | 등록된 계정의 사용자를 확인하고, 확인된 역할(고객 또는 관리자)에 따라 시스템 이용 권한을 부여한다. |
| 사전 조건 | 1. 로그인하려는 계정이 시스템에 등록되어 있어야 한다. (고객 계정은 C-01 회원가입으로 생성되며, 관리자 계정은 사전에 등록된 계정을 사용한다.)<br>2. 현재 로그인되지 않은 상태이어야 한다. |
| 입력 정보 | 계정 ID, 비밀번호 |
| 처리 내용 | 1. 계정 ID와 비밀번호가 모두 입력되었는지 확인한다.<br>2. 입력한 계정 ID를 정규화(NFKC, 양끝 공백 제거)하고, 대소문자를 구분하지 않고 해당하는 계정이 등록되어 있는지 조회한다.<br>3. 입력한 비밀번호를 해시 처리한 결과가 해당 계정에 저장된 비밀번호 해시 값과 일치하는지 검증한다.<br>4. 검증에 성공하면 해당 계정에 지정된 역할(CUSTOMER 또는 ADMIN)을 확인한다.<br>5. 인증된 사용자와 그 역할을 현재 접속에 대하여 유지하여, 이후의 요청을 로그인된 사용자의 요청으로 인식한다.<br>6. 확인된 역할에 따라 이용 가능한 기능을 제공한다. CUSTOMER에게는 고객 전용 기능(C-02 ~ C-09)을, ADMIN에게는 관리자 전용 기능(A-01 ~ A-03)을 제공한다. 고객 전용 기능 중 C-02 ~ C-05는 로그인 없이도 이용할 수 있으며, C-06 ~ C-09는 CUSTOMER로 로그인한 경우에만 이용할 수 있다. |
| 출력 정보 | - 성공 시: 로그인 완료 결과, 사용자의 역할, 역할에 따른 이용 가능 기능<br>- 실패 시: 로그인 실패 안내 메시지 |
| 예외 및 제약사항 | 1. 계정 ID 또는 비밀번호가 입력되지 않은 경우 로그인을 수행하지 않고 입력을 요청한다.<br>2. 등록되지 않은 계정 ID이거나 비밀번호가 일치하지 않는 경우 로그인에 실패하며 로그인 상태를 생성하지 않는다. 이때 계정 ID와 비밀번호 중 어느 쪽이 틀렸는지 구분하지 않고 동일한 안내 메시지를 제공한다.<br>3. CUSTOMER는 관리자 전용 기능(A-01 ~ A-03)을 이용할 수 없다. (BR-13)<br>4. ADMIN은 고객 전용 기능(C-02 ~ C-09)의 담당 사용자가 아니다.<br>5. 로그인은 영화·상영 일정 조회(C-02, C-03), 좌석 현황 조회(C-04), 좌석 선택(C-05)의 이용 조건이 아니며, 예매 확정(C-06) 시점부터 필수이다. 로그인하지 않은 방문자는 로그인된 세션이 없는 접근을 의미하며 별도의 계정 역할이 아니다. 시스템의 계정 역할은 CUSTOMER와 ADMIN 두 가지뿐이다. (BR-05, D4) |

#### 3.1.2 CM-02 로그아웃

| 항목 | 내용 |
|---|---|
| 업무 ID | CM-02 |
| 업무명 | 로그아웃 |
| 담당 사용자 | CUSTOMER, ADMIN |
| 업무 목적 | 현재 로그인된 접속을 종료하여, 다시 로그인하기 전까지 인증이 필요한 기능을 이용할 수 없도록 한다. |
| 사전 조건 | CUSTOMER 또는 ADMIN으로 로그인된 상태이어야 한다. |
| 입력 정보 | 현재 로그인된 사용자의 접속 정보 |
| 처리 내용 | 1. 현재 접속이 로그인된 상태인지 확인한다.<br>2. 현재 접속에 유지되고 있는 인증된 사용자 정보와 역할 정보를 삭제한다.<br>3. 이후 인증이 필요한 기능을 요청하면 로그인되지 않은 요청으로 처리하여 로그인을 요구한다. |
| 출력 정보 | 로그아웃 완료 결과 (로그인되지 않은 상태로 전환) |
| 예외 및 제약사항 | 1. 이미 로그인되어 있지 않은 상태에서 로그아웃을 요청하더라도 오류로 처리하지 않고 로그인되지 않은 상태를 유지한다.<br>2. 로그아웃 이후 예매 확정(C-06), 모의 결제(C-07), 예매 내역 조회(C-08), 예매 취소(C-09) 및 관리자 전용 기능(A-01 ~ A-03)은 다시 로그인하기 전까지 이용할 수 없다. (BR-05, BR-09, BR-13)<br>3. 영화·상영 일정 조회(C-02, C-03), 좌석 현황 조회(C-04), 좌석 선택(C-05)은 로그인 없이 이용할 수 있으므로 로그아웃 이후에도 계속 이용할 수 있다. (D4) |

#### 3.1.3 C-01 회원가입

| 항목 | 내용 |
|---|---|
| 업무 ID | C-01 |
| 업무명 | 회원가입 |
| 담당 사용자 | CUSTOMER |
| 업무 목적 | 신규 이용자가 직접 고객(CUSTOMER) 계정을 생성하여 예매 업무를 이용할 수 있도록 한다. |
| 사전 조건 | 로그인되지 않은 상태에서 사용할 신규 계정 정보를 보유하고 있어야 한다. |
| 입력 정보 | 계정 ID, 비밀번호 |

| 처리 내용 | 1. 로그인 여부와 사용자 역할을 확인한다. 로그인되어 있지 않으면 CM-01 로그인을 요구하고 예매를 진행하지 않는다.<br>2. 선택한 상영 일정이 존재하는지 확인한다.<br>3. 좌석의 중복 여부를 확인하기 전에, 결제 기한이 지난 미결제 예매에 대하여 만료 처리를 먼저 수행한다.<br>4. 현재 시각이 해당 상영 일정의 상영 시작 시각 이전인지 확인한다.<br>5. 선택된 좌석이 한 개 이상인지 확인한다.<br>6. 선택된 모든 좌석이 해당 상영 일정의 상영관에 속한 좌석인지 확인한다.<br>7. 선택된 모든 좌석에 대하여, 해당 상영 일정에 유효한 예매가 이미 존재하는지 다시 확인한다.<br>8. 위 확인 사항을 모두 통과하면 총 예매 금액을 '상영 일정의 좌석당 관람 가격 × 선택된 좌석 수'로 계산한다.<br>9. 예매 확정 처리 시각을 예매 일시(`booked_at`)로 기록하고, 결제 기한(`expires_at`)을 `booked_at` + 10분으로 계산한다.<br>10. 로그인한 고객, 상영 일정, 예매 일시, 결제 기한, 총 예매 금액을 포함하는 예매를 저장한다. 이때 예매 상태는 `BOOKED`, 결제 상태는 `UNPAID`로 지정한다.<br>11. 예매에 포함된 모든 좌석의 상세 정보(좌석, 예매 시점에 적용된 좌석별 가격)를 예매와 함께 저장한다. 예매와 모든 좌석 상세 정보의 저장은 모두 성공하거나 모두 실패하도록 처리하며, 일부 좌석만 저장된 예매를 남기지 않는다.<br>12. 예매 확정 결과를 제공하고 C-07 모의 결제로 연결한다. 예매가 저장된 시점부터 해당 좌석은 결제 기한까지 점유된다. |
| 출력 정보 | - 성공 시: 예매 확정 결과, 예매 번호, 예매 내용(영화, 상영 일정, 상영관, 예매 좌석, 좌석별 가격, 총 예매 금액), 예매 일시, 결제 기한, 예매 상태(`BOOKED`, 예매 완료), 결제 상태(`UNPAID`, 미결제)<br>- 실패 시: 실패 사유 안내 메시지 |
| 예외 및 제약사항 | 1. 로그인되지 않은 경우 예매를 확정할 수 없다. (BR-05, D4)<br>2. ADMIN은 본 업무의 담당 사용자가 아니다.<br>3. 상영이 이미 시작된 상영 일정은 예매할 수 없다. (BR-12)<br>4. 선택한 좌석 중 하나라도 해당 상영 일정의 상영관에 속하지 않으면 예매를 확정하지 않는다. (BR-07)<br>5. 선택한 좌석 중 하나라도 같은 상영 일정에 이미 유효한 예매가 있으면(다른 고객이 먼저 예매한 경우 포함) 예매 전체를 확정하지 않고, 일부 좌석만 예매하지 않는다. 중복 예매를 방지하며, 사용자에게 좌석 재선택을 안내한다. (BR-08)<br>6. 하나의 예매는 하나의 상영 일정에 속하며 한 번에 중복 없이 1~50개(상영관 정원)의 좌석을 포함할 수 있다. (BR-06)<br>7. 예매 확정 단계에서는 결제를 처리하지 않으며, 결제는 C-07 모의 결제에서 처리한다. (BR-15)<br>8. 결제 기한은 예매 확정이 성공적으로 기록된 시점부터 10분이며, 좌석 선택 시점부터 계산하지 않는다. 결제 기한 내에 C-07에서 결제가 완료되지 않으면 예매는 `EXPIRED`로 변경되고 좌석이 해제된다. (D3)<br>9. 상영 일정에 설정된 좌석당 관람 가격을 적용하며, 예매 시점에 각 좌석에 적용된 가격을 예매 좌석 상세 정보에 저장하고 총 예매 금액을 예매 본 정보에 저장한다. 영화관 전체에 적용되는 단일 고정 가격은 사용하지 않는다. (D6) |

#### 3.3.3 C-07 모의 결제

| 항목 | 내용 |
|---|---|
| 업무 ID | C-07 |
| 업무명 | 모의 결제 |
| 담당 사용자 | CUSTOMER |
| 업무 목적 | 외부 결제 서비스 없이 결제 절차를 모의로 수행하여, 결제 기한 내에 예매의 결제 상태를 `PAID`(결제 완료)로 변경한다. |
| 사전 조건 | 1. CUSTOMER로 로그인되어 있어야 한다.<br>2. 결제할 예매가 존재하며 본인의 예매이어야 한다.<br>3. 해당 예매의 예매 상태가 `BOOKED`이고 결제 상태가 `UNPAID`이어야 한다.<br>4. 현재 시각이 해당 예매의 결제 기한(`expires_at`)보다 엄격하게 이르어야 한다. |
| 입력 정보 | 로그인한 고객 정보, 결제할 예매 선택 정보, 결제 진행(모의 결제 요청) 의사, 현재 시각 |
| 처리 내용 | 1. 로그인 여부와 사용자 역할을 확인한다.<br>2. 결제를 처리하기 전에, 결제 기한이 지난 미결제 예매에 대하여 만료 처리를 먼저 수행한다.<br>3. 결제 대상 예매가 존재하는지 확인한다.<br>4. 결제 대상 예매가 로그인한 고객 본인의 예매인지 확인한다.<br>5. 예매 상태가 `BOOKED`인지, 결제 상태가 `UNPAID`인지 확인한다.<br>6. 현재 시각이 `expires_at`보다 엄격하게 이른지 확인한다. 현재 시각이 `expires_at`과 같거나 이후이면 결제를 거부하고, 예매 상태가 아직 EXPIRED로 변경되지 않은 미결제 예매는 EXPIRED로 변경하고 관련 예매 좌석 상세 정보를 삭제한다.<br>7. 외부 결제 서비스와 연동하지 않고, 결제가 정상적으로 완료된 것으로 모의 처리한다.<br>8. 모의 결제가 성공하면 해당 예매의 결제 상태를 `PAID`로 변경한다.<br>9. 결제 결과와 변경된 결제 상태를 제공한다. |
| 출력 정보 | - 성공 시: 모의 결제 완료 결과, 예매 내용, 예매 상태(`BOOKED`, 예매 완료), 결제 상태(`PAID`, 결제 완료)<br>- 실패 시: 실패 사유 안내 메시지 (결제 기한 경과로 인한 만료 포함) |
| 예외 및 제약사항 | 1. 결제는 모의로 처리하며 실제 결제 서비스(결제 게이트웨이)를 사용하지 않는다. 카드 정보 등 실제 결제 정보를 입력받거나 저장하지 않는다. (BR-15)<br>2. 본인의 예매가 아닌 경우 결제를 수행하지 않는다. (BR-09)<br>3. 결제는 예매 상태가 `BOOKED`이고 결제 상태가 `UNPAID`이며 현재 시각이 `expires_at`보다 엄격하게 이른 경우에만 허용한다. 현재 시각이 `expires_at`과 같거나 이후에 완료되는 결제는 거부한다. (D3)<br>4. 이미 `CANCELLED`인 예매는 결제할 수 없다.<br>5. 이미 `EXPIRED`인 예매는 결제할 수 없으며, 다시 활성화할 수 없다. 좌석이 아직 예매 가능한 경우 고객은 새로 예매해야 한다. (D3)<br>6. 이미 `PAID`인 예매는 다시 결제하지 않는다. 결제가 완료된 예매는 결제 기한 규칙에 따라 만료되지 않으며 좌석을 계속 점유한다. (D3)<br>7. 모의 결제가 완료되지 않은 경우 결제 상태를 `UNPAID`로 유지하며, 이 경우에도 결제 기한이 지나면 예매는 만료 처리된다. (D3)<br>8. 만료 처리로 인하여 예매가 `EXPIRED`로 변경된 경우 결제 상태는 `UNPAID`로 유지된다. (D3)<br>9. 환불 처리 기능은 본 시스템의 범위에 포함하지 않는다. (BR-15) |

#### 3.3.4 C-08 예매 내역 조회

| 항목 | 내용 |
|---|---|
| 업무 ID | C-08 |
| 업무명 | 예매 내역 조회 |
| 담당 사용자 | CUSTOMER |
| 업무 목적 | 고객이 본인의 예매 내역(취소 및 만료된 예매 포함)을 확인하고, 예매 취소 및 결제 대상을 선택할 수 있도록 한다. |
| 사전 조건 | CUSTOMER로 로그인되어 있어야 한다. |
| 입력 정보 | 로그인한 고객 정보, 현재 시각 |
| 처리 내용 | 1. 로그인 여부와 사용자 역할을 확인한다.<br>2. 예매 상태가 현재 시각 기준으로 정확하게 제공되도록, 결제 기한이 지난 미결제 예매에 대하여 만료 처리를 먼저 수행한다.<br>3. 로그인한 고객 본인의 예매만 조회 대상으로 한정한다.<br>4. 본인의 예매 내역을 예매 상태와 관계없이 모두 조회한다. `CANCELLED` 및 `EXPIRED` 예매도 포함한다.<br>5. 각 예매에 대하여 예매 번호, 영화(제목 및 `poster_url`), 상영 일정, 상영관, 좌석당 가격, 총 예매 금액, 예매 일시, 예매 상태, 결제 상태를 함께 조회한다.<br>6. 예매 상태가 `BOOKED`인 예매에 대해서는 예매 좌석 상세 정보에서 예매 좌석을 함께 조회하고, 결제 상태가 `UNPAID`이면 결제 기한을 함께 조회한다. 예매 좌석 상세 정보가 삭제된 `CANCELLED` 및 `EXPIRED` 예매는 좌석 목록을 조회하지 않는다.<br>7. 예매 일시 내림차순(최신순, `booked_at DESC, booking_id DESC`)으로 정렬하여 제공한다.<br>8. 예매 상태가 `BOOKED`이고 상영이 시작되기 전인 예매에 대해서는 예매 취소(C-09)를, 예매 상태가 `BOOKED`이고 결제 상태가 `UNPAID`인 예매에 대해서는 모의 결제(C-07)를 요청할 수 있도록 연결한다. |

| 예외 및 제약사항 | 1. 로그인되지 않은 경우 예매 내역을 제공하지 않고 CM-01 로그인을 요구한다.<br>2. 다른 고객의 예매는 조회할 수 없으며, 다른 고객의 예매를 지정하여 요청하더라도 접근을 허용하지 않는다. (BR-09)<br>3. 취소된 예매와 만료된 예매의 본 정보는 이력으로 계속 조회할 수 있어야 한다. (BR-11, D1, D3)<br>4. `CANCELLED` 및 `EXPIRED` 예매는 예매 좌석 상세 정보가 삭제되어 있으므로, 원래의 좌석 목록을 보유하고 있거나 제공할 수 있는 것처럼 표시하거나 안내하지 않는다. 이러한 예매에 대해서는 보존된 예매 본 정보(예매 번호, 상영 일정, 예매 일시, 총 예매 금액, 예매 상태, 결제 상태)만 제공한다. (D1, D3)<br>5. 결제 완료 후 취소된 예매는 결제 상태가 `PAID`로, 만료된 예매는 결제 상태가 `UNPAID`로 그대로 표시된다. 환불 정보는 제공하지 않는다. (D1, D3)<br>6. 예매 내역이 없는 경우 예매 내역이 없음을 안내한다.<br>7. 전체 고객의 예매 조회는 관리자 전용 기능인 A-03 예매 목록 조회에서 수행한다. |

| 출력 정보 | - 성공 시: 예매 취소 완료 결과, 보존된 예매 본 정보(예매 번호, 상영 일정, 총 예매 금액), 예매 상태(`CANCELLED`, 취소), 결제 상태(취소 이전 상태 유지), 좌석이 해제되었음을 알리는 안내<br>- 실패 시: 실패 사유 안내 메시지 |
| 예외 및 제약사항 | 1. 로그인되지 않은 경우 예매를 취소할 수 없으며 CM-01 로그인을 요구한다.<br>2. 본인의 예매가 아닌 경우 취소를 허용하지 않는다. (BR-09)<br>3. 상영이 이미 시작된 예매는 취소할 수 없다. (BR-10)<br>4. 이미 `CANCELLED`인 예매는 다시 취소할 수 없다.<br>5. 결제 기한이 지나 `EXPIRED`로 변경된 예매는 취소할 수 없으며 다시 활성화할 수도 없다. 고객은 새로 예매해야 한다. (D3)<br>6. 예매를 취소하면 하나의 예매에 포함된 모든 좌석을 함께 취소하며, 예매 좌석 상세 정보를 모두 삭제하여 좌석을 해제한다. 해제된 좌석은 C-04에서 '예매 가능'으로 조회되며 다른 고객이 예매할 수 있다. (BR-11, D1)<br>7. 취소된 예매의 본 정보는 삭제하지 않고 이력으로 보존한다. 보존된 이력은 C-08(본인) 및 A-03(관리자)에서 조회할 수 있다. 다만 예매 좌석 상세 정보가 삭제되므로 취소된 예매의 정확한 좌석 목록은 제공하지 않는다. (BR-11, D1)<br>8. 예매에 포함된 좌석 중 일부만 취소하는 기능은 제공하지 않는다.<br>9. 결제가 완료된 예매를 취소하더라도 결제 상태는 `PAID`로 유지되고 예매 상태만 `CANCELLED`로 변경된다. 환불 처리 기능은 본 시스템의 범위에 포함하지 않는다. (BR-15, D1) |

(BR-13)<br>2. 필수 정보가 누락되었거나 값이 유효하지 않은 경우 영화를 등록하거나 변경하지 않고 오류를 안내한다.<br>3. 수정·삭제 대상 영화가 존재하지 않는 경우 처리를 수행하지 않고 오류를 안내한다.<br>4. 영화 수정은 기존 상영 일정에 예매가 있더라도 허용되며, `duration_minutes`를 변경해도 이미 만들어진 상영 일정의 종료 시각(`ends_at`)은 바뀌지 않는다. (BR-03, D2)<br>5. 삭제 시 해당 영화의 상영 일정 중 하나라도 이미 시작되었거나 예매 기록(`BOOKED`, `CANCELLED`, `EXPIRED`)이 존재하면 영화와 모든 상영 일정을 보존하고 삭제를 거부한다(`409 movie_delete_blocked`).<br>6. 영화 정보는 기본 6개 속성(`title`, `genre`, `duration_minutes`, `rating`, `synopsis`, `release_date`)과 선택적 포스터 경로(`poster_url`)로 구성한다. 영화를 구분하는 식별자(`movie_id`)는 시스템이 생성하는 기술적 키이다. #### 3.4.2 A-02 상영 일정 관리

| 항목 | 내용 |
|---|---|
| 업무 ID | A-02 |
| 업무명 | 상영 일정 관리 |
| 담당 사용자 | ADMIN |
| 업무 목적 | 관리자가 상영 일정을 추가하고, 아직 시작되지 않았으며 예매 기록이 없는 상영 일정에 한하여 수정하거나 삭제하되, 같은 상영관에서 상영 시간이 겹치지 않도록 관리한다. |
| 사전 조건 | 1. ADMIN으로 로그인되어 있어야 한다.<br>2. 추가·수정 시 상영 일정에 연결할 영화와 상영관이 등록되어 있어야 한다. |
| 입력 정보 | - 상영 일정 추가: 영화(`movie_id`), 상영관(`room_id`), 상영 시작 시각(`starts_at`), 상영 종료 시각(`ends_at`, 생략 가능), 좌석당 관람 가격(`ticket_price`)<br>- 상영 일정 수정: 수정할 상영 일정의 식별자, 변경할 정보(추가와 동일한 전체 필드 교체)<br>- 상영 일정 삭제: 삭제할 상영 일정의 식별자 |
| 처리 내용 | 1. 로그인 여부와 사용자 역할이 ADMIN인지 확인한다.<br>2. 업무 구분(추가, 수정, 삭제)을 확인한다.<br>3. 수정의 경우 대상 상영 일정을 잠그고 존재 여부 및 이미 시작되었는지(`starts_at <= clock_timestamp()`)를 먼저 확인한다. 이미 시작된 상영 일정이면 수정을 거부한다.<br>4. 수정의 경우 대상 상영 일정을 참조하는 예매 기록(`BOOKINGS`)이 하나라도 존재하는지 확인한다. 예매 상태(`BOOKED`, `CANCELLED`, `EXPIRED`)와 관계없이 예매 기록이 존재할 때 `movie_id`, `room_id`, `starts_at`, `ends_at`, `ticket_price` 중 하나라도 변경하려 하면 수정을 거부한다(동일한 값으로 저장하는 무변경 요청은 허용).<br>5. 추가·수정의 경우 지정된 영화와 상영관이 존재하는지 확인하고, 시작 시각·종료 시각(`ends_at` 생략 시 `starts_at + 영화 상영 시간`으로 자동 계산, 명시 시 `ends_at > starts_at`)·좌석당 관람 가격(0 이상의 유한 값)을 검증한다.<br>6. 같은 상영관에 등록된 다른 상영 일정과 `[starts_at, ends_at)` 구간이 겹치는지 확인한다(수정 시 자신은 제외; 직전 상영의 종료 시각과 같은 시각에 시작하는 연속 편성은 허용).<br>7. 겹치는 상영 일정이 없으면 추가의 경우 새 상영 일정을 등록하고, 수정의 경우 선택된 상영 일정의 정보를 변경한다.<br>8. 삭제의 경우 대상 상영 일정을 잠근 뒤 존재 여부를 확인하고, 아직 시작되지 않았으며(`starts_at > clock_timestamp()`) 참조하는 `BOOKINGS` 기록이 전혀 없는 경우에만 삭제한다. 시작되었거나 예매 기록이 있으면 삭제를 거부한다.<br>9. 처리 결과와 등록·변경된 상영 일정 정보(또는 삭제 완료)를 제공한다. |
| 출력 정보 | - 추가·수정 성공 시: 등록 또는 수정된 상영 일정 정보(영화, 상영관, 상영 시작 시각, 상영 종료 시각, 좌석당 관람 가격, `has_started`, `has_bookings`)와 처리 완료 결과<br>- 삭제 성공 시: 상영 일정 삭제 완료 결과<br>- 수정·삭제 거부 시: 이미 시작되었거나 예매 기록이 존재하여 처리할 수 없다는 안내 메시지<br>- 충돌 시: 같은 상영관의 기존 상영 일정과 시간이 겹친다는 충돌 안내 메시지<br>- 실패 시: 실패 사유 안내 메시지 |
| 예외 및 제약사항 | 1. 상영 일정의 추가·수정·삭제는 관리자만 수행할 수 있으며, 로그인하지 않았거나 CUSTOMER인 경우 접근을 허용하지 않는다. (BR-13)<br>2. 하나의 상영 일정은 하나의 영화와 하나의 상영관에 연결되어야 한다. (BR-03)<br>3. 같은 상영관의 상영 일정은 `[starts_at, ends_at)` 구간이 겹칠 수 없다(정비 간격 등 추가 버퍼 없음). 겹치는 상영 일정이 제출되면 저장·변경하지 않는다. (BR-04)<br>4. 서로 다른 상영관의 상영 일정은 시간이 같더라도 충돌로 보지 않는다.<br>5. 이미 상영이 시작된 상영 일정(`starts_at <= clock_timestamp()`)은 수정 및 삭제할 수 없다(`409 screening_has_started` / `409 screening_delete_blocked`).<br>6. 상영 일정을 참조하는 예매 기록(`BOOKED`, `CANCELLED`, `EXPIRED`)이 하나라도 존재하면 해당 상영 일정의 5개 속성(`movie_id`, `room_id`, `starts_at`, `ends_at`, `ticket_price`) 변경 및 상영 일정 삭제를 허용하지 않는다(`409 screening_has_bookings` / `409 screening_delete_blocked`). 이는 과거 예매의 상영 일정 맥락과 이력의 일관성을 보존하기 위한 것이다. (D2)<br>7. 예매 기록이 없고 아직 시작되지 않은 상영 일정만 수정·삭제할 수 있으며, 새로운 상영 일정의 추가는 기존 규칙을 충족하는 한 허용된다. (D2)<br>8. 좌석당 관람 가격은 상영 일정별로 정의하며(0 이상 유한 `numeric(10,2)`), 영화관 전체에 적용되는 단일 고정 가격은 사용하지 않는다. 초기 데이터의 금액(12,000원)은 시연 데이터이며 업무 규칙이 아니다. (D2, D6)<br>9. 필수 정보가 누락되었거나 종료 시각이 시작 시각 이하이거나 지정한 영화·상영관이 존재하지 않는 경우 등록·변경을 수행하지 않고 오류를 안내한다. |

| 사전 조건 | ADMIN으로 로그인되어 있어야 한다. |
| 입력 정보 | 로그인한 관리자 정보, 선택적 조회 필터(`status`: `BOOKED`/`CANCELLED`/`EXPIRED`, `screening_id`, `user_id`), 현재 시각 |
| 처리 내용 | 1. 로그인 여부와 사용자 역할이 ADMIN인지 확인한다.<br>2. 선택적 필터(`status`, `screening_id`, `user_id`)가 전달된 경우 유효성을 검증한다.<br>3. 예매 상태가 현재 시각 기준으로 정확하게 제공되도록, 결제 기한이 지난 미결제 예매에 대하여 만료 처리를 먼저 수행한다.<br>4. 조회 대상을 필터 조건과 일치하는 전체 고객의 예매로 조회한다. `CANCELLED` 및 `EXPIRED` 예매도 포함한다.<br>5. 각 예매에 대하여 예매 번호, 예매한 고객(`user_id`, `username`), 영화, 상영 일정, 상영관, 좌석당 가격, 총 예매 금액, 예매 일시, 예매 상태, 결제 상태를 함께 조회한다.<br>6. 예매 상태가 `BOOKED`인 예매에 대해서는 예매 좌석 상세 정보에서 예매 좌석을 함께 조회하고, 결제 상태가 `UNPAID`이면 결제 기한을 함께 조회한다. 예매 좌석 상세 정보가 삭제된 `CANCELLED` 및 `EXPIRED` 예매는 좌석 목록을 빈 목록으로 반환한다.<br>7. 예매 일시 내림차순(최신순, `booked_at DESC, booking_id DESC`)으로 정렬하여 제공한다. |
| 출력 정보 | 전체 예매 목록: 예매 번호, 예매한 고객, 영화, 상영 일정, 상영관, 좌석당 가격, 총 예매 금액, 예매 일시, 예매 상태(`BOOKED` 예매 완료, `CANCELLED` 취소, `EXPIRED` 만료), 결제 상태(`UNPAID` 미결제, `PAID` 결제 완료)<br>- `BOOKED` 예매에 한하여: 예매 좌석, (미결제인 경우) 결제 기한 |
| 예외 및 제약사항 | 1. 전체 예매 목록은 관리자만 조회할 수 있으며, 로그인하지 않았거나 CUSTOMER인 경우 접근을 허용하지 않는다.<br>2. 고객은 본인의 예매만 조회할 수 있다. (BR-09)<br>3. 조건에 맞는 예매가 없는 경우 빈 목록을 반환한다.<br>4. 취소된 예매와 만료된 예매의 본 정보도 조회 대상에 포함한다. (BR-11, D1, D3)<br>5. `CANCELLED` 및 `EXPIRED` 예매는 예매 좌석 상세 정보가 삭제되어 있으므로, 좌석 목록을 제공하지 않는다(`seats: []`). 이러한 예매에 대해서는 보존된 예매 본 정보(예매 번호, 고객, 상영 일정, 예매 일시, 총 예매 금액, 예매 상태, 결제 상태)만 제공한다. (D1, D3)<br>6. 결제 완료 후 취소된 예매는 결제 상태가 `PAID`로, 만료된 예매는 결제 상태가 `UNPAID`로 그대로 표시된다. 환불 정보는 제공하지 않는다. (D1, D3)<br>7. 본 업무는 예매를 조회만 하며, 관리자가 예매를 생성·변경·취소하는 기능은 포함하지 않는다. |

## 4. 단위 업무 요약

| 업무 ID | 업무명 | 담당 사용자 | 주요 처리 내용 |
|---|---|---|---|
| CM-01 | 로그인 | CUSTOMER, ADMIN | 계정 ID와 비밀번호(해시 값 대조)를 검증하고 역할을 확인하여 역할별 이용 권한을 부여한다. |
| CM-02 | 로그아웃 | CUSTOMER, ADMIN | 인증된 접속 정보를 삭제하여 재로그인 전까지 인증 기능(C-06 ~ C-09, A-01 ~ A-03)의 이용을 차단한다. |
| C-01 | 회원가입 | CUSTOMER | 계정 ID와 비밀번호만 입력받아 검증하고 계정 ID 중복을 확인한 후, 비밀번호를 해시 처리하고 역할을 CUSTOMER로 고정하여 계정을 생성한다. |
| C-02 | 영화 목록 및 상세 조회 | CUSTOMER | 로그인 없이 등록된 영화의 목록과 선택한 영화의 상세 정보(기본 6개 속성 + 선택적 `poster_url`)를 조회하여 제공한다. |
| C-03 | 상영 일정 조회 | CUSTOMER | 로그인 없이 영화와 날짜를 기준으로 상영 시각, 상영관, 좌석당 관람 가격이 포함된 상영 일정을 조회한다. |
| C-04 | 좌석 현황 조회 | CUSTOMER | 로그인 없이 만료 처리를 먼저 수행한 후, 유효한 예매를 기준으로 상영 일정별 좌석의 예매 가능 여부를 판정하여 제공한다. |
| C-05 | 좌석 선택 | CUSTOMER | 로그인 없이 상영관 소속 여부와 예매 가능 여부를 확인하여 한 개 이상의 좌석을 임시로 선택한다. 좌석을 점유하지 않으며 결제 기한도 시작되지 않는다. |
| C-06 | 예매 확정 | CUSTOMER | 로그인, 만료 처리, 상영 시작 전 여부, 좌석 소속 및 중복 예매 여부를 확인하고 총 금액을 계산하여 `BOOKED` + `UNPAID` 예매와 모든 좌석 상세 정보를 함께 저장하고, 결제 기한(예매 일시 + 10분)을 설정한다. |
| C-07 | 모의 결제 | CUSTOMER | 본인의 `BOOKED` + `UNPAID` 예매에 대하여 결제 기한 이전에 한하여 결제를 모의로 처리하고 결제 상태를 `PAID`로 변경한다. 기한 이후의 결제는 거부한다. |
| C-08 | 예매 내역 조회 | CUSTOMER | 로그인한 고객 본인의 예매를 취소 및 만료된 예매를 포함하여 최신순으로 조회한다. 취소 및 만료된 예매는 좌석 목록 없이 예매 본 정보만 제공한다. |
| C-09 | 예매 취소 | CUSTOMER | 본인의 `BOOKED` 예매에 대하여 상영 시작 전 여부를 확인하고, 예매 상태를 `CANCELLED`로 변경하며 모든 좌석 상세 정보를 삭제하여 좌석을 해제하되 예매 본 정보는 이력으로 보존한다. |
| A-01 | 영화 관리 | ADMIN | 기본 6개 속성과 선택적 포스터 경로로 영화를 추가·수정하고, 시작되었거나 예매 이력이 있는 상영 일정이 없을 때 영화를 삭제한다. |
| A-02 | 상영 일정 관리 | ADMIN | 영화, 상영관, 좌석당 관람 가격을 지정하여 상영 일정을 추가한다. 이미 시작된 상영 일정은 수정·삭제할 수 없으며, 예매 기록이 하나라도 있으면 실제 변경 및 삭제를 거부한다. |
| A-03 | 예매 목록 조회 | ADMIN | 모든 고객과 상영 일정의 전체 예매를 취소 및 만료된 예매를 포함하여 최신순(선택 필터 지원)으로 조회한다. 취소 및 만료된 예매는 좌석 목록 없이 예매 본 정보만 제공한다. |
