# 프로젝트 개요서

**프로젝트명:** 영화관 예매 및 좌석 관리 시스템 (Cinema Reservation System)

---

## 1. 프로젝트 개요

본 프로젝트는 영화관의 영화 정보, 상영 일정, 좌석, 예매 정보를 데이터베이스로 체계적으로 관리하고, 이용자가 웹 환경에서 영화 조회부터 좌석 선택, 예매, 모의 결제, 예매 취소까지 수행할 수 있도록 하는 **영화관 예매 및 좌석 관리 시스템**을 설계하고 구현하는 데이터베이스 설계 프로젝트이다.

시스템은 일반 이용자인 고객(CUSTOMER)과 시스템 운영자인 관리자(ADMIN)의 두 가지 역할을 지원한다. 고객은 영화와 상영 일정을 조회하고 좌석을 선택하여 예매하며, 관리자는 영화와 상영 일정을 관리하고 전체 예매 내역을 조회한다.

### 1.1 시스템 규모

| 구분 | 내용 |
|---|---|
| 영화관 수 | 1개 |
| 상영관 수 | 5개 |
| 상영관별 좌석 수 | 50석 |
| 전체 좌석 수 | 250석 (5개 상영관 × 50석) |
| 샘플 영화 수 | 6편 |
| 상영 일정 수 | 280회 (연속 14일간, 하루 20회) |
| 사용자 역할 | 2종 (CUSTOMER, ADMIN) |

---

## 2. 프로젝트 배경 및 목적

### 2.1 프로젝트 배경

영화관 예매 업무는 영화, 상영관, 좌석, 상영 일정, 예매 정보가 서로 밀접하게 연관되어 있는 대표적인 데이터 중심 업무이다. 특히 동일한 상영 일정에 대하여 같은 좌석이 중복 예매되어서는 안 되며, 동일한 상영관에서 상영 시간이 겹치는 일정이 등록되어서도 안 된다. 또한 예매가 취소되더라도 예매 이력은 보존되어야 한다. 이러한 요구사항은 데이터의 무결성과 일관성을 보장하는 데이터베이스 설계의 필요성을 잘 보여준다.

### 2.2 프로젝트 목적

본 프로젝트의 목적은 다음과 같다.

1. 영화관 예매 업무를 분석하여 업무 규칙을 정의하고, 이를 반영한 관계형 데이터베이스를 설계한다.
2. 좌석 중복 예매 방지, 상영 일정 중복 방지, 예매 이력 보존 등 데이터 무결성이 요구되는 업무를 데이터베이스 수준에서 관리할 수 있도록 한다.
3. 고객과 관리자의 역할에 따라 사용할 수 있는 기능을 구분한 웹 기반 응용 시스템을 구현한다.
4. 데이터베이스 설계 결과를 실제 동작하는 응용 프로그램과 연계하여 검증한다.

## 3. 프로젝트 범위

### 3.1 시스템 환경 범위

| 항목 | 범위 |
|---|---|
| 영화관 | 1개 |
| 상영관 | 5개 |
| 좌석 | 상영관당 50석, 총 250석 |
| 영화 | 샘플 영화 6편 |
| 상영 일정 | 연속 14일간 총 280회 |
| 사용자 역할 | CUSTOMER, ADMIN |
| 사전 등록 관리자 계정 | ADMIN 계정 1개 |
| 사전 등록 고객 데모 계정 | CUSTOMER 데모 계정 2개 |

### 3.2 기능 범위

본 프로젝트에 포함되는 기능은 다음과 같다.

| 구분 | 포함 기능 |
|---|---|
| 회원 | 고객 회원가입, 로그인, 로그아웃 (로그인·로그아웃은 고객·관리자 공통) |
| 조회 | 영화 목록 조회, 영화 상세 조회, 상영 일정 조회, 좌석 현황 조회 |
| 예매 | 좌석 선택, 예매 확정, 모의 결제 |
| 예매 관리 | 예매 내역 조회, 예매 취소 |
| 관리자 | 영화 관리, 상영 일정 관리, 예매 목록 조회 |

### 3.3 범위 외 사항

다음 사항은 본 프로젝트의 범위에 포함하지 않는다.

- 복수 영화관 운영 및 5개를 초과하는 상영관 관리
- 실제 결제 대행 서비스(결제 게이트웨이) 연동

위의 승인된 범위 외의 기능은 본 프로젝트에 포함하지 않는다.

## 4. 사용자 정의

본 시스템의 사용자는 CUSTOMER와 ADMIN의 두 가지 역할로 구분한다.

| 구분 | CUSTOMER (고객) | ADMIN (관리자) |
|---|---|---|
| 정의 | 영화를 조회하고 좌석을 예매하는 일반 이용자 | 영화와 상영 일정을 관리하고 예매 현황을 확인하는 시스템 운영자 |
| 계정 생성 | 회원가입을 통해 직접 생성 | 회원가입으로 생성할 수 없음 |
| 주요 권한 | 영화·상영 일정·좌석 현황 조회, 좌석 선택, 예매 확정, 모의 결제, 본인 예매 내역 조회, 본인 예매 취소 | 영화 추가·수정·조건부 삭제, 상영 일정 추가·수정·조건부 삭제, 전체 예매 목록 조회 |
| 공통 권한 | 로그인, 로그아웃 | 로그인, 로그아웃 |
| 제한 사항 | 영화 및 상영 일정을 추가·수정·삭제할 수 없음. 타인의 예매를 조회하거나 취소할 수 없음 | — |

공개 회원가입을 통해서는 CUSTOMER 계정만 생성할 수 있으며, 영화 및 상영 일정의 추가·수정·삭제는 관리자만 수행할 수 있다.

## 5. 주요 기능

### 5.1 공통 기능 (CUSTOMER, ADMIN)

| 번호 | 기능 | 설명 |
|---|---|---|
| CM-01 | 로그인 | CUSTOMER와 ADMIN이 계정으로 시스템에 접속한다. |
| CM-02 | 로그아웃 | CUSTOMER와 ADMIN이 시스템 접속을 종료한다. |

### 5.2 고객(CUSTOMER) 전용 기능

| 번호 | 기능 | 설명 |
|---|---|---|
| C-01 | 회원가입 | 고객 계정을 생성한다. 공개 회원가입은 CUSTOMER 계정만 생성할 수 있으며, ADMIN은 회원가입으로 생성할 수 없다. |
| C-02 | 영화 목록 및 상세 조회 | 등록된 영화 목록과 영화별 상세 정보를 조회한다. |
| C-03 | 상영 일정 조회 | 영화별 상영 일정을 조회한다. |
| C-04 | 좌석 현황 조회 | 선택한 상영 일정의 좌석별 예매 가능 여부를 조회한다. |
| C-05 | 좌석 선택 | 예매 가능한 좌석을 한 개 이상 선택한다. |
| C-06 | 예매 확정 | 선택한 좌석에 대한 예매를 확정한다. 로그인한 고객만 수행할 수 있다. |
| C-07 | 모의 결제 | 실제 결제 없이 결제 절차를 모의로 처리한다. |
| C-08 | 예매 내역 조회 | 본인의 예매 내역을 조회한다. |
| C-09 | 예매 취소 | 상영 시작 전에 한하여 본인의 예매를 취소한다. 하나의 예매에 포함된 모든 좌석이 함께 취소된다. |

### 5.3 관리자(ADMIN) 전용 기능

| 번호 | 기능 | 설명 |
|---|---|---|
| A-01 | 영화 관리 | 영화를 추가하고 영화 정보를 수정하며, 이미 시작되었거나 예매 이력이 있는 상영 일정이 없는 경우에 한하여 영화를 삭제한다(예매 이력이 없는 향후 상영 일정도 함께 삭제). |
| A-02 | 상영 일정 관리 | 상영 일정을 추가하고 수정하며, 아직 시작되지 않았고 예매 이력이 없는 상영 일정을 삭제한다. 동일 상영관의 상영 시간은 중복될 수 없다. |
| A-03 | 예매 목록 조회 | 전체 예매 내역을 조회한다. |

## 6. 업무 규칙

본 시스템은 다음의 업무 규칙을 따른다.

### 6.1 상영관 및 좌석

| 번호 | 업무 규칙 |
|---|---|
| BR-01 | 하나의 상영관은 여러 개의 좌석을 가진다. |
| BR-02 | 하나의 좌석은 반드시 하나의 상영관에만 속한다. |

### 6.2 상영 일정

| 번호 | 업무 규칙 |
|---|---|
| BR-03 | 하나의 상영 일정은 하나의 영화와 하나의 상영관에 연결된다. |
| BR-04 | 같은 상영관의 상영 일정은 시간이 서로 겹칠 수 없다. |

### 6.3 예매

| 번호 | 업무 규칙 |
|---|---|
| BR-05 | 고객은 예매를 확정하기 전에 반드시 로그인해야 한다. |
| BR-06 | 하나의 예매는 하나의 상영 일정에 속하며, 여러 개의 좌석을 포함할 수 있다. |
| BR-07 | 선택한 좌석은 해당 상영 일정의 상영관에 속한 좌석이어야 한다. |
| BR-08 | 하나의 좌석은 같은 상영 일정에서 유효한(active) 예매를 하나만 가질 수 있다. |

### 6.4 예매 조회, 취소 및 시간 제한

| 번호 | 업무 규칙 |
|---|---|
| BR-09 | 고객은 본인의 예매만 조회하고 취소할 수 있다. |
| BR-10 | 예매는 상영이 시작되기 전까지 취소할 수 있다. |
| BR-11 | 예매를 취소하면 하나의 예매에 포함된 모든 좌석을 함께 취소하며, 취소된 좌석은 다시 예매할 수 있도록 해제한다. 취소된 예매의 이력은 보존된다. |
| BR-12 | 상영이 시작된 이후에는 해당 상영 일정을 예매할 수 없다. |

### 6.5 권한 및 결제

| 번호 | 업무 규칙 |
|---|---|
| BR-13 | 영화와 상영 일정의 추가, 수정 및 삭제는 관리자만 수행할 수 있다. |
| BR-14 | 공개 회원가입으로는 CUSTOMER 계정만 생성할 수 있다. |
| BR-15 | 결제는 모의로 처리하며, 실제 결제 게이트웨이는 사용하지 않는다. |

## 7. 개발 환경

| 구분 | 기술 | 용도 |

## 8. 기대 효과

1. **업무 규칙의 체계화:** 영화관 예매 업무의 규칙을 명확히 정의하여 데이터베이스 설계의 기준으로 활용할 수 있다.
2. **데이터 무결성 확보:** 좌석 중복 예매와 상영 일정 중복을 방지하는 규칙을 반영하여 데이터의 일관성을 유지할 수 있다.
3. **이력 관리:** 예매가 취소되더라도 예매 이력이 보존되므로 예매 내역을 추적할 수 있다.
4. **역할 기반 업무 분리:** 고객과 관리자의 권한을 구분하여 영화·상영 일정 관리와 예매 업무를 분리할 수 있다.
5. **설계 결과의 검증:** 데이터베이스 설계를 웹 응용 시스템과 연계하여 실제 업무 흐름에서 검증할 수 있다.
